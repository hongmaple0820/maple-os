## 1. Mixture-of-Agents (MoA)

### 动机

单模型推理存在盲区。MoA 通过并行调用多个 LLM（不同模型/不同温度），然后聚合结果，提升推理质量和鲁棒性。参考 Together AI 的 MoA 论文和 hermes-agent 的多模型策略。

### 核心概念

```
                    ┌─────────────┐
                    │  Aggregator  │  ← 合并/投票/选择最佳
                    └──────┬──────┘
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         ┌─────────┐ ┌─────────┐ ┌─────────┐
         │ Model A  │ │ Model B  │ │ Model C  │  ← 并行推理
         │ (GPT-4)  │ │(Claude)  │ │(Local)   │
         └─────────┘ └─────────┘ └─────────┘
```

### 数据结构

```rust
/// MoA 请求配置
pub struct MoAConfig {
    /// 参与推理的模型列表
    pub models: Vec<MoAModel>,
    /// 聚合策略
    pub strategy: AggregationStrategy,
    /// 并行超时（秒）
    pub timeout_secs: u64,
    /// 最少需要几个模型响应
    pub min_responses: usize,
}

pub struct MoAModel {
    pub model_id: String,
    pub adapter: Arc<dyn LlmAdapter>,
    pub temperature: Option<f32>,
    pub weight: f64,  // 投票权重
}

/// 聚合策略
pub enum AggregationStrategy {
    /// 多数投票（适用于分类/判断题）
    MajorityVote,
    /// 加权投票（按模型权重）
    WeightedVote,
    /// 最长最佳（适用于代码生成）
    LongestBest,
    /// 评委模式：用一个模型从多个结果中选最佳
    JudgeModel { judge_adapter: Arc<dyn LlmAdapter> },
    /// 自定义聚合函数
    Custom(Arc<dyn Fn(&[MoAResponse]) -> MoAResponse + Send + Sync>),
}

/// 单个模型的响应
pub struct MoAResponse {
    pub model_id: String,
    pub content: String,
    pub input_tokens: u64,
    pub output_tokens: u64,
    pub latency_ms: u64,
    pub finish_reason: String,
}

/// MoA 最终结果
pub struct MoAResult {
    pub selected: MoAResponse,
    pub all_responses: Vec<MoAResponse>,
    pub aggregation_reason: String,
}
```

### API 设计

```rust
pub struct MixtureOfAgents {
    config: MoAConfig,
}

impl MixtureOfAgents {
    pub fn new(config: MoAConfig) -> Self;

    /// 并行推理 + 聚合
    pub async fn reason(&self, request: &LlmRequest) -> Result<MoAResult>;

    /// 仅并行推理，不聚合（用于对比分析）
    pub async fn reason_all(&self, request: &LlmRequest) -> Result<Vec<MoAResponse>>;
}
```

### 集成点

- **LlmRouter**: MoA 作为 `LlmAdapter` 的一个包装器，可以被路由规则引用
- **ReactLoop**: 通过 `with_moa(config)` 注入，替代默认的单模型调用
- **DelegationEngine**: 子代理可以使用 MoA 配置进行高质量推理

### 实现计划

| 步骤 | 内容 | 复杂度 |
|------|------|--------|
| 1 | `MoAConfig`, `MoAModel`, `MoAResponse` 结构体 | S |
| 2 | `MixtureOfAgents::reason_all()` 并行调用 | M |
| 3 | 5 种聚合策略实现 | M |
| 4 | 实现 `LlmAdapter` trait 适配 | S |
| 5 | 集成到 `ReactLoop` | S |
| 6 | 测试 + 边界情况 | M |

## 2. Trident Compaction

### 动机

当前 `ContextCompressor` 使用单阶段压缩（head protect + middle summarize + tail protect）。Trident 是 claw-code 的三阶段压缩策略，更精细地处理上下文窗口：

1. **Supersede（取代）**: 如果新消息完全替代旧消息（如重新编辑同一文件），删除旧版本
2. **Collapse（折叠）**: 将连续的工具调用链折叠为摘要
3. **Cluster（聚类）**: 按主题/任务聚类，每簇只保留摘要

### 核心概念

```
原始消息流:
  [sys] [user] [tool1] [tool2] [tool3] [assistant] [user] [tool4] [tool5] [assistant]

Stage 1 - Supersede:
  tool2 内容是 tool1 的更新版本 → 删除 tool1
  结果: [sys] [user] [tool2] [tool3] [assistant] [user] [tool4] [tool5] [assistant]

Stage 2 - Collapse:
  [tool2, tool3] 是同一任务的工具链 → 折叠为摘要
  [tool4, tool5] 同理
  结果: [sys] [user] [collapsed_summary_1] [assistant] [user] [collapsed_summary_2] [assistant]

Stage 3 - Cluster:
  两个 cluster 都是 "文件编辑" 主题 → 合并为一个 cluster 摘要
  结果: [sys] [user] [cluster_summary] [assistant]
```

### 数据结构

```rust
pub struct TridentConfig {
    /// Stage 1: 启用 Supersede
    pub enable_supersede: bool,
    /// Stage 2: 启用 Collapse
    pub enable_collapse: bool,
    /// Stage 3: 启用 Cluster
    pub enable_cluster: bool,
    /// Supersede 检测：内容相似度阈值（0.0-1.0）
    pub supersede_similarity_threshold: f64,
    /// Collapse: 连续工具消息超过此数量才折叠
    pub collapse_min_chain: usize,
    /// Cluster: 最大聚类数
    pub max_clusters: usize,
    /// 每聚类最大 token 数
    pub max_cluster_tokens: usize,
}

impl Default for TridentConfig {
    fn default() -> Self {
        Self {
            enable_supersede: true,
            enable_collapse: true,
            enable_cluster: true,
            supersede_similarity_threshold: 0.7,
            collapse_min_chain: 3,
            max_clusters: 5,
            max_cluster_tokens: 2000,
        }
    }
}

/// 压缩操作日志
pub enum CompactionAction {
    Supersede { removed_idx: usize, kept_idx: usize, reason: String },
    Collapse { range: Range<usize>, summary: String },
    Cluster { indices: Vec<usize>, summary: String },
}
```

### API 设计

```rust
pub struct TridentCompactor {
    config: TridentConfig,
    token_counter: Arc<dyn TokenCounter>,
}

impl TridentCompactor {
    pub fn new(config: TridentConfig, token_counter: Arc<dyn TokenCounter>) -> Self;

    /// 执行三阶段压缩
    pub fn compact(&self, messages: &[Message]) -> (Vec<Message>, Vec<CompactionAction>);

    /// 仅执行 Stage 1（Supersede）
    pub fn supersede(&self, messages: &[Message]) -> (Vec<Message>, Vec<CompactionAction>);

    /// 仅执行 Stage 2（Collapse）
    pub fn collapse(&self, messages: &[Message]) -> (Vec<Message>, Vec<CompactionAction>);

    /// 仅执行 Stage 3（Cluster）
    pub fn cluster(&self, messages: &[Message]) -> (Vec<Message>, Vec<CompactionAction>);
}
```

### 集成点

- **ContextCompressor**: `TridentCompactor` 替代现有的 `prune_tool_outputs` 三阶段
- **ReactLoop**: `compress()` 方法调用 `TridentCompactor::compact()`
- **SessionStore**: 压缩后的消息保存 `CompactionAction` 日志用于调试

### 实现计划

| 步骤 | 内容 | 复杂度 |
|------|------|--------|
| 1 | `TridentConfig`, `CompactionAction` 结构体 | S |
| 2 | Stage 1: Supersede — 基于文件路径/工具名 + 内容相似度检测 | M |
| 3 | Stage 2: Collapse — 连续工具链检测 + LLM 摘要 | M |
| 4 | Stage 3: Cluster — 基于消息 embedding 或关键词聚类 | L |
| 5 | 集成到 `ContextCompressor` | S |
| 6 | 测试 + 压缩率验证 | M |

## 3. Lane Events + Policy Engine

### 动机

当前 `Orchestrator` 使用简单的拓扑排序执行 plan steps。Lane Events 是 claw-code 的并行工作流管理方案，将任务分配到独立的 "lane"（泳道），每个 lane 有独立的事件流和策略约束。

### 核心概念

```
┌─────────────────────────────────────────────────┐
│                   Orchestrator                    │
├─────────────┬─────────────┬─────────────────────┤
│   Lane A    │   Lane B    │      Lane C          │
│  (Code Gen) │  (Testing)  │   (Documentation)    │
│  [policy]   │  [policy]   │     [policy]         │
│  events→    │  events→    │     events→          │
│  step1      │  step3      │     step5            │
│  step2      │  step4      │                      │
└─────────────┴─────────────┴─────────────────────┘
         ↑              ↑               ↑
         └──────────────┴───────────────┘
              Policy Engine evaluates rules
```

### 数据结构

```rust
/// 泳道：一组有序步骤 + 策略约束
pub struct Lane {
    pub id: String,
    pub name: String,
    pub steps: Vec<String>,  // step IDs
    pub policy: LanePolicy,
    pub status: LaneStatus,
}

pub enum LaneStatus {
    Idle,
    Running { current_step: String },
    Completed,
    Failed { step: String, error: String },
    Paused { reason: String },
}

/// 泳道策略
pub struct LanePolicy {
    /// 最大并发工具数（覆盖全局设置）
    pub max_concurrent_tools: Option<usize>,
    /// 步骤间最小间隔（秒）
    pub min_step_interval_secs: Option<u64>,
    /// 失败时行为
    pub on_failure: FailurePolicy,
    /// 需要人工审批的步骤
    pub requires_approval: Vec<String>,
    /// 允许的工具子集
    pub allowed_tools: Option<Vec<String>>,
}

pub enum FailurePolicy {
    /// 停止整个 lane
    Abort,
    /// 跳过失败步骤
    Skip,
    /// 重试 N 次
    Retry { max_attempts: u32 },
    /// 回退到上一个检查点
    Rollback,
}

/// Lane 事件
pub enum LaneEvent {
    LaneStarted { lane_id: String },
    StepStarted { lane_id: String, step_id: String },
    StepCompleted { lane_id: String, step_id: String, output: String },
    StepFailed { lane_id: String, step_id: String, error: String },
    LaneCompleted { lane_id: String },
    LaneFailed { lane_id: String, error: String },
    ApprovalRequested { lane_id: String, step_id: String, approval_id: String },
    ApprovalResolved { approval_id: String, approved: bool },
}

/// 策略规则
pub struct PolicyRule {
    pub id: String,
    pub name: String,
    pub condition: PolicyCondition,
    pub action: PolicyAction,
}

pub enum PolicyCondition {
    /// Lane 完成后触发
    OnLaneComplete(String),
    /// 步骤失败时触发
    OnStepFailure(String),
    /// 工具调用前检查
    BeforeToolUse(String),
    /// 时间条件
    AfterDuration(Duration),
    /// 自定义条件
    Custom(Arc<dyn Fn(&LaneContext) -> bool + Send + Sync>),
}

pub enum PolicyAction {
    /// 允许继续
    Allow,
    /// 阻止执行
    Deny { reason: String },
    /// 暂停 lane
    Pause { reason: String },
    /// 重定向到另一个 lane
    Redirect { target_lane: String },
    /// 触发事件
    EmitEvent(LaneEvent),
}
```

### API 设计

```rust
pub struct LaneManager {
    lanes: Vec<Lane>,
    rules: Vec<PolicyRule>,
    event_tx: mpsc::Sender<LaneEvent>,
    event_log: Vec<LaneEvent>,
}

impl LaneManager {
    pub fn new() -> (Self, mpsc::Receiver<LaneEvent>);

    /// 从 ExecutionPlan 创建 lanes
    pub fn from_plan(plan: &ExecutionPlan) -> Self;

    /// 添加泳道
    pub fn add_lane(&mut self, lane: Lane);

    /// 添加策略规则
    pub fn add_rule(&mut self, rule: PolicyRule);

    /// 获取下一个可执行的步骤（跨所有 lanes）
    pub fn next_executable(&self) -> Option<(String, String)>; // (lane_id, step_id)

    /// 标记步骤完成
    pub fn complete_step(&mut self, lane_id: &str, step_id: &str, output: String) -> Result<()>;

    /// 标记步骤失败
    pub fn fail_step(&mut self, lane_id: &str, step_id: &str, error: String) -> Result<()>;

    /// 检查策略
    pub fn check_policy(&self, context: &LaneContext) -> PolicyAction;

    /// 获取事件日志
    pub fn event_log(&self) -> &[LaneEvent];
}
```

### 集成点

- **Orchestrator**: `execute_plan()` 使用 `LaneManager` 替代简单的拓扑排序
- **DelegationEngine**: 步骤执行通过 `delegate()` 完成
- **MailboxRouter**: Lane 事件可以通过 mailbox 广播

### 实现计划

| 步骤 | 内容 | 复杂度 |
|------|------|--------|
| 1 | `Lane`, `LanePolicy`, `LaneStatus` 结构体 | S |
| 2 | `LaneEvent` 事件系统 | S |
| 3 | `PolicyRule`, `PolicyCondition`, `PolicyAction` | M |
| 4 | `LaneManager` 核心逻辑 | M |
| 5 | 与 `Orchestrator` 集成 | M |
| 6 | 策略引擎求值器 | M |
| 7 | 测试 + 并发安全验证 | M |

## 4. In-Process Multi-Agent

### 动机

当前 `DelegationEngine` 为每个子代理创建独立的 `ReactLoop`，开销较大。In-process multi-agent 使用轻量级上下文隔离（类似 Node.js 的 AsyncLocalStorage），在同一个 tokio task 内运行多个 "虚拟代理"，共享底层资源但隔离状态。

### 核心概念

```
┌─────────────────────────────────────────┐
│              Tokio Task                   │
│  ┌─────────────┐  ┌─────────────┐        │
│  │ AgentCtx A   │  │ AgentCtx B   │       │
│  │ (scope)      │  │ (scope)      │       │
│  │ - session    │  │ - session    │       │
│  │ - tools      │  │ - tools      │       │
│  │ - permissions│  │ - permissions│       │
│  └──────┬───────┘  └──────┬───────┘       │
│         │                 │               │
│         └────────┬────────┘               │
│                  ▼                        │
│         Shared Resources                  │
│         - LlmAdapter (Arc)               │
│         - ToolExecutor (Arc)             │
│         - MemoryManager (Arc)            │
└─────────────────────────────────────────┘
```

### 数据结构

```rust
use std::cell::RefCell;
use std::sync::Arc;

/// 轻量级代理上下文（类似 AsyncLocalStorage）
pub struct AgentContext {
    pub agent_id: String,
    pub parent_id: Option<String>,
    pub session: Session,
    pub tools: Vec<String>,
    pub permissions: PermissionLevel,
    pub depth: u32,
    pub metadata: HashMap<String, String>,
}

tokio::task_local! {
    static AGENT_CONTEXT: RefCell<Option<AgentContext>>;
}

/// In-process 代理管理器
pub struct InProcessAgentManager {
    /// 共享的 LLM 适配器
    adapter: Arc<dyn LlmAdapter>,
    /// 共享的工具执行器
    tool_executor: Arc<dyn ToolExecutor>,
    /// 共享的内存管理器
    memory: Arc<MemoryManager>,
    /// 最大嵌套深度
    max_depth: u32,
    /// 活跃代理计数
    active_count: Arc<AtomicU32>,
}

/// 代理执行结果
pub struct AgentResult {
    pub agent_id: String,
    pub output: String,
    pub iterations: usize,
    pub tokens_used: u64,
}
```

### API 设计

```rust
impl InProcessAgentManager {
    pub fn new(
        adapter: Arc<dyn LlmAdapter>,
        tool_executor: Arc<dyn ToolExecutor>,
        memory: Arc<MemoryManager>,
    ) -> Self;

    /// 在 task-local 上下文中运行代理
    pub async fn run_agent<F, Fut, T>(
        &self,
        context: AgentContext,
        f: F,
    ) -> Result<T>
    where
        F: FnOnce() -> Fut,
        Fut: Future<Output = Result<T>>;

    /// 获取当前代理上下文
    pub fn current_context() -> Result<AgentContext>;

    /// 派生子代理（继承父上下文）
    pub async fn spawn_child<F, Fut, T>(
        &self,
        child_id: String,
        tools: Vec<String>,
        f: F,
    ) -> Result<T>
    where
        F: FnOnce() -> Fut,
        Fut: Future<Output = Result<T>>;
}
```

### 集成点

- **DelegationEngine**: 轻量级 `delegate_in_process()` 方法
- **ReactLoop**: 可以从 task-local 上下文获取代理元数据
- **MemoryManager**: 子代理可以访问父代理的 memory scope

### 实现计划

| 步骤 | 内容 | 复杂度 |
|------|------|--------|
| 1 | `AgentContext` 结构体 + `task_local!` 宏 | S |
| 2 | `InProcessAgentManager` 核心逻辑 | M |
| 3 | `run_agent()` 上下文注入/清除 | M |
| 4 | `spawn_child()` 子代理派生 | M |
| 5 | 与 `DelegationEngine` 集成 | S |
| 6 | 并发安全测试 | M |

## 5. Dynamic Skill Discovery

### 动机

当前工具/技能在编译时或启动时注册。Dynamic Skill Discovery 根据运行时上下文（文件路径、任务类型、用户偏好）动态激活/停用技能。参考 hermes-agent 的条件激活机制。

### 核心概念

```
┌─────────────────────────────────────────┐
│           Skill Registry                  │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐    │
│  │ Skill A  │ │ Skill B  │ │ Skill C  │   │
│  │ active   │ │ dormant  │ │ active   │   │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘   │
│       │            │            │         │
│       ▼            ▼            ▼         │
│  ┌─────────────────────────────────────┐  │
│  │         Activation Engine            │  │
│  │  - File path patterns (*.rs → Rust) │  │
│  │  - Task type (code_gen → CodeSkill) │  │
│  │  - User preference (always use TDD) │  │
│  │  - Context signals (has tests/)     │  │
│  └─────────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 数据结构

```rust
/// 技能定义
pub struct Skill {
    pub id: String,
    pub name: String,
    pub description: String,
    /// 技能提供的工具列表
    pub tools: Vec<String>,
    /// 激活条件
    pub activation_rules: Vec<ActivationRule>,
    /// 是否当前激活
    pub active: bool,
    /// 优先级（多个技能冲突时）
    pub priority: i32,
}

/// 激活规则
pub enum ActivationRule {
    /// 文件路径 glob 匹配
    FilePath { pattern: String },
    /// 目录存在
    DirectoryExists { path: String },
    /// 任务类型匹配
    TaskType(TaskType),
    /// 用户显式启用
    UserEnabled,
    /// 关键词出现在用户消息中
    Keyword { words: Vec<String> },
    /// 文件内容匹配（如 package.json 存在 "react"）
    FileContains { path: String, pattern: String },
    /// 自定义条件
    Custom(Arc<dyn Fn(&SkillContext) -> bool + Send + Sync>),
    /// 组合条件（AND）
    All(Vec<ActivationRule>),
    /// 组合条件（OR）
    Any(Vec<ActivationRule>),
}

/// 技能评估上下文
pub struct SkillContext {
    pub workspace_root: String,
    pub current_files: Vec<String>,
    pub task_type: Option<TaskType>,
    pub user_message: String,
    pub active_skills: Vec<String>,
}

/// 技能管理器
pub struct SkillDiscovery {
    skills: Vec<Skill>,
    workspace_root: String,
}
```

### API 设计

```rust
impl SkillDiscovery {
    pub fn new(workspace_root: String) -> Self;

    /// 注册技能
    pub fn register(&mut self, skill: Skill);

    /// 评估所有技能的激活状态
    pub fn evaluate(&mut self, context: &SkillContext) -> Vec<SkillActivation>;

    /// 获取当前激活的工具集
    pub fn active_tools(&self) -> Vec<String>;

    /// 获取激活/停用变更
    pub fn diff(&self, previous: &[String]) -> SkillDiff;
}

pub struct SkillActivation {
    pub skill_id: String,
    pub active: bool,
    pub reason: String,
}

pub struct SkillDiff {
    pub activated: Vec<String>,
    pub deactivated: Vec<String>,
}
```

### 集成点

- **ReactLoop**: 每轮 `run_turn` 前调用 `SkillDiscovery::evaluate()` 更新可用工具
- **ToolUseContext**: 动态更新 `allowed_tools` 列表
- **LlmRequest**: 将激活的技能描述注入系统提示

### 实现计划

| 步骤 | 内容 | 复杂度 |
|------|------|--------|
| 1 | `Skill`, `ActivationRule`, `SkillContext` 结构体 | S |
| 2 | `ActivationRule` 求值器（glob 匹配、文件检测） | M |
| 3 | `SkillDiscovery::evaluate()` 批量评估 | M |
| 4 | `SkillDiff` 变更检测 | S |
| 5 | 与 `ReactLoop` 集成 | S |
| 6 | 预定义技能模板 | S |
| 7 | 测试 | M |

## 6. Memory Provider Lifecycle Hooks

### 动机

当前 `MemoryManager` 直接使用 `maple_kb::MemoryStore`。Memory Provider Lifecycle Hooks 允许：
- 自定义存储后端（Redis、SQLite、文件系统）
- 记忆写入前/后的转换（加密、压缩、过滤）
- 记忆过期策略（TTL、LRU、手动清理）
- 记忆同步（多设备/多代理共享）

```rust
    /// 加载后钩子（可过滤或转换）

    /// 过期钩子
    async fn on_expire(&self, entry: &MemoryEntry) -> Result<()>;
}

    Modified,
}
```

## 7. Trajectory Compression

### 动机

Agent 的完整推理轨迹（每一步的思考、工具调用、结果）是宝贵的训练数据，但原始轨迹太长且噪声大。Trajectory Compression 将长轨迹压缩为高质量的训练样本，用于微调或 RLHF。

### 核心概念

```
原始轨迹:
  [思考1] → [工具A] → [结果A] → [思考2] → [工具B] → [结果B] → [思考3] → [完成]
    │                    │                    │                    │
    └── decision point   └── feedback         └── decision point   └── outcome

压缩后:
  {
    task: "实现用户认证",
    decisions: [
      { thought: "选择 JWT", action: "implement_jwt", outcome: "success" },
      { thought: "添加刷新机制", action: "add_refresh", outcome: "success" }
    ],
    tools_used: ["read_file", "write_file", "run_tests"],
    final_outcome: "success",
    quality_score: 0.85
  }
```

### 数据结构

```rust
/// 压缩后的训练轨迹

    pub steps: Vec<TrajectoryStep>,
```

### API 设计

```rust
pub struct TrajectoryCompressor {
    config: TrajectoryCompressionConfig,
    scorer: TrajectoryScorer,
    token_counter: Arc<dyn TokenCounter>,
}

impl TrajectoryCompressor {
    pub fn new(
        config: TrajectoryCompressionConfig,
        token_counter: Arc<dyn TokenCounter>,
    ) -> Self;

    /// 从原始会话轨迹生成训练样本
    pub async fn compress(
        &self,
        session: &Session,
        task_description: &str,
        adapter: Option<&dyn LlmAdapter>,
    ) -> Result<TrainingTrajectory>;

    /// 批量压缩多个会话
    pub async fn compress_batch(
        &self,
        sessions: &[(Session, String)],
        adapter: Option<&dyn LlmAdapter>,
    ) -> Result<Vec<TrainingTrajectory>>;

    /// 评分
    pub fn score(&self, trajectory: &TrainingTrajectory) -> f64;

    /// 导出为 JSONL 训练格式
    pub fn to_jsonl(trajectories: &[TrainingTrajectory]) -> String;
}

impl TrajectoryScorer {
    pub fn score(&self, trajectory: &TrainingTrajectory) -> f64 {
        let completion = self.score_completion(trajectory);
        let efficiency = self.score_efficiency(trajectory);
        let decision_quality = self.score_decisions(trajectory);
        let tool_usage = self.score_tool_usage(trajectory);

        self.weights.completion * completion
            + self.weights.efficiency * efficiency
            + self.weights.decision_quality * decision_quality
            + self.weights.tool_usage * tool_usage
    }
}
```

### 集成点

- **SessionStore**: 从持久化的会话中提取轨迹
- **MemoryManager**: 高质量轨迹可以存入长期记忆
